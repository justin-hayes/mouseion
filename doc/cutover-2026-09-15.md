# Migration Baseline Cutover: 2026-09-15

This note records the one-time cutover required by [ADR 0070](adr/0070-migration-and-documentation-reboot.md).
The baseline has no upgrade path from the retired migration sequence. Recreating
the database is therefore destructive and must be treated as a break-glass
operation, not as a normal deployment step.

## Optional pre-cutover backup

The backup is manual and is not part of Compose or any deployment automation.
Run it before stopping the old stack if the existing learner data needs
insurance:

```sh
docker compose exec -T db pg_dump -U mouseion --format=custom --dbname=mouseion \
  > /tmp/mouseion-pre-cutover-YYYYMMDD.dump
sha256sum /tmp/mouseion-pre-cutover-YYYYMMDD.dump
```

## Development recreation

The commands below remove only the PostgreSQL data volume. They preserve the
NLP model volume, so the cutover does not needlessly redownload Stanza models.
Confirm the volume name with `docker volume ls` before running the removal.
Ensure `.env` contains a strong `MOUSEION_SECRET` before starting the web
container; the Compose fallback is intentionally not suitable for deployment.

```sh
docker compose down
docker volume rm mouseion_db-data
docker compose up -d --build
docker compose ps
docker compose exec -T db pg_isready -U mouseion -d mouseion
docker compose exec -T web /mouseion-server healthcheck
```

The web process runs the embedded baseline migration before opening its health
endpoint. A healthy `web` container therefore verifies both database startup
and application startup. The first-account sign-in flow remains the expected
way to create a learner on the recreated database.

This verification used the local Compose stack. A remote home-lab deployment
was not independently reachable from this checkout; an operator must run the
same recreation and healthcheck procedure in that deployment environment.

## Integration recreation

Integration tests reset a disposable PostgreSQL database and replay the full
embedded migration set whenever a test acquires the database. Use the shared
target when running the suite locally so one fresh database is reused safely:

```sh
make test-integration-shared
```

The repository acceptance command is:

```sh
make test-integration
```

The CI integration job currently runs its narrower package selection directly:

```sh
go test -tags=integration ./internal/persistence ./internal/prepareddeck ./internal/webapp
```

The shared target requires Docker when `MOUSEION_TEST_DATABASE_URL` is not set;
an explicit test URL is supported for an operator-managed PostgreSQL instance.
